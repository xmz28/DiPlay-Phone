# ESP32 车辆 BLE 与融合仪表

更新：2026-10-15。

## 使用

在 DiPlay 设置中的“车辆数据 · ESP32 BLE”选择车辆 ESP32，允许附近设备权限并完成系统配对。选择后开启后台车辆连接；后续只按已绑定的完整 BLE 地址重连，不自动换成信号更强的另一辆车。关闭开关会停止车辆连接，CarPlay 会话独立保留。

车辆连接成功后，融合仪表显示车速、挡位、功率、电量、电压、电流、ESP32 累计里程和车辆指示灯。地图、音乐、封面仍由现有 CarPlay 链路提供。仪表页面每 50 ms 刷新一次，仅在页面可见时运行刷新任务。

BLE 断连、关闭连接开关或 3 秒没有收到有效状态包时，整套仪表恢复原来的演示数值和演示指示灯。连接仍在但某个车辆字段无效时，该字段显示“--”，不会用演示数字冒充车辆数据。当前协议没有续航字段，实时连接时续航显示“--”；里程来自 ESP32 根据速度累计，不代表车辆原厂总里程。

## 协议兼容

服务 UUID 为 `7d2e4001-6b3a-4f1b-9c7d-5a0e2f6b1001`，通知与认证写入特征分别使用 `4002`、`4003`。保留现有版本 1、12 字节分片头、20 Hz 实时包和 1 Hz 全量包。

实时 JSON 新增字段：

| 字段 | 含义 |
|---|---|
| `uv` | 电压整数，单位 0.1 V |
| `ia` | 有符号电流整数，单位 0.1 A；保留负电流 |
| `ea` | 电气采样距发送时刻的年龄，单位 ms |
| `z` 第 3 位 | 电压有效 |
| `z` 第 4 位 | 电流有效 |

原 `p` 保持单位 0.1 kW，原 `v` 仍表示状态版本、原 `i` 仍表示指示灯位图。新字段是增量扩展，旧客户端可忽略；新版手机收到旧固件时仍显示原功率，电压、电流显示未知。

电压与电流都有效时，手机用 `U × I / 1000` 计算功率，计算过程不先舍入，仪表显示两位小数。缺少有效电气数据时回退到有效的旧功率字段（显示一位小数）。两位小数是显示分辨率，不是测量精度承诺。

电气字段具有独立采样年龄，不能由其他车辆状态刷新掩盖过期。ESP32 超过 5 秒未收到电气采样会清除电气有效位，Android 同时检查 `ea`。较慢的全量包只合并电量和里程，不覆盖更新的实时速度、电气值和指示灯。只有全量包到达时，缺失的实时字段会变为无效。

## 来源与边界

- CAN `0x0C20FFD2`：电压原始值 / 10；电流原始值 / 10 − 500。两者来自同一帧。
- RS485 `0xDA`：同样按 0.1 V / 0.1 A 解码，并检查无效哨兵。
- RS485 `0xD2`：原始分辨率只有 1 V / 1 A，编码成十分之一单位不增加原始测量精度。
- 未增加车辆总线控制命令，未把尚未确认含义的原始转速值当作真实转速。
- 沿用 ESP32 的配对及本机随机令牌认证，不记录令牌内容。当前板端最多保存两个可信令牌；不同 App 各占一个。认证连接仍遵循板端原有的 GPIO2 感应解锁指示行为。
- 新增后台服务只负责车辆 BLE，和 CarPlay、屏幕镜像各自独立。
- 只复用了遥测模型与传输逻辑，未复制原私有仪表图片、图标或 UI 资源；公开仪表继续使用现有自行绘制的图标。

## 验证

已完成 ESP32 构建并烧录确认的目标板、MyApplication 构建与 2 项功率测试、DiPlay 构建及 19 项协议/分片/超时/布局测试。实车电压、电流和并行 CarPlay 行为需以实际连接记录为准；不把单元测试示例数值作为实测数据。

### 红米与目标 ESP32 验证（2026-10-15）

- DiPlay 测试版已安装到 Redmi K30 5G，车辆 BLE 和 CarPlay 同时运行。
- 多个约 5 秒统计窗口收到 98～99 个实时包，约 19.5～19.7 Hz；这些窗口没有检测到序号缺包。短时间观测不能代替长期稳定性测试。
- 板端演示数据：72.8 V、16.5 A → 1.20 kW；负电流 −16.5 A → −1.20 kW，数值、符号与显示均核对。
- 目标 ESP32 复位期间，画面恢复 DiPlay 原默认演示值及演示指示灯，CarPlay 地图保持显示；复位后自动重连原绑定设备并恢复板端数值。
- 用户确认当前未接实车。本轮验证的是 BLE、解析、仪表显示和 CarPlay 并行；CAN/RS485 实车采样精度、实车灯态及长期稳定性尚未验证。
- MyApplication 新 APK 已构建，未在本轮重新安装或做实机验收。
